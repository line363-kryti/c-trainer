Большую программу делят на модули: каждый отвечает за свою часть работы.
Файл `.h` описывает интерфейс — объявления функций, типы и общие макросы.
Файл `.c` содержит реализацию и подключает свой заголовок.

```c
/* calc.h */
#ifndef CALC_H
#define CALC_H
int add(int a, int b);       /* объявление */
#endif

/* calc.c — отдельный файл */
#include "calc.h"
int add(int a, int b) { return a + b; } /* определение */
```

`#include` вставляет текст заголовка до компиляции. Защита `#ifndef / #define / #endif`
не даёт обработать его повторно в одной единице трансляции. В лекции также показан `#pragma once`.

Сборка проходит четыре этапа: **препроцессор → компилятор → ассемблер → линкер**.

```sh
gcc -E main.c                      # препроцессор
gcc -S main.c                      # ассемблерный текст
gcc -c main.c -o main.o            # объектный файл
gcc main.c calc.c -o program       # сборка обоих модулей
```

Без `calc.c` линкер выдаст `undefined reference`. Обычную функцию не определяют в `.h`:
при подключении из нескольких `.c` можно получить `multiple definition`.
Подключать `.c` вместо `.h` тоже не следует.

**Практика на сайте:** функции пока находятся в одном файле. Задание из лекции
с отдельными `calc.h`, `calc.c` и `main.c` выполни в своей IDE: сайт ещё не проверяет многофайловые проекты.
